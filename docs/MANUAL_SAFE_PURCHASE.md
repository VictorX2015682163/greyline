# 2 × 4 保险箱人工收款

玩家在「保险箱 → 查看购买」复制自己的购买编号，通过微信给收款人支付 10 元并提供编号。收款人在自己的微信账单核对实际到账、金额和交易单号后，使用发码工具生成该编号的专属激活码，微信发回给买家。买家粘贴后即可永久解锁并装备 2 × 4 保险箱。

付款不会自动解锁，玩家自己点击按钮也不能直接确认到账。普通微信收款码本身不提供聊天入口；买家应已有你的微信联系方式，也可以在配置中填写想展示的微信号。

## 首次配置

在项目目录执行，依赖 Python 3.10+ 和 OpenSSL：

```sh
python3 tools/safe_box_admin.py setup
python3 tools/safe_box_admin.py configure --qr '/绝对路径/你的微信收款码.png'
# 如果需要在购买页公开微信号，可选填：
python3 tools/safe_box_admin.py configure --wechat '你的微信号'
```

本次开发已初始化本机发码密钥；再次运行 setup 会复用已有密钥。私钥在 `~/.local/share/greyline-merchant/signing_private.pem`，订单记录在同目录 `orders.jsonl`，两者只留在商家电脑，不放进游戏目录或发给玩家。请一起备份，以便补发原激活码。游戏仅包含公开验签密钥。

收款码会复制到 `assets/payments/wechat_collection.png` 或 `.jpg`，配置保存在 `data/manual_safe_purchase.json`。用 Godot 打开项目完成新图片导入，重新打开购买页即可看到图片。导出游戏时确保包含 `data/*.json` 和收款码资源。收款码或验签公钥未就绪时，购买页不会展示可付款码。

## 确认到账后发码

将买家发来的完整 `GL-` 购买编号和你在微信账单看到的实际到账交易单号代入：

```sh
python3 tools/safe_box_admin.py issue --buyer 'GL-购买页完整编号' --receipt '微信实际到账交易单号'
```

工具输出整段 `GL1.` 开头的激活码，把整段通过微信发给该买家即可。重复输入相同到账单号和购买编号会返回原码；同一到账单号不能为不同编号重复发码。工具不连接微信、不自动验证付款，也不会代你发送微信消息。

签名包含商品、10 元价格、购买编号和唯一交易标识；游戏使用公钥校验签名，拒绝改动内容、其他商品、其他买家的激活码。只有商家电脑的私钥可以签发有效码。

## 档案与恢复

购买编号和永久权限保存在 `user://profile.json`。玩家需保留自己的档案；删除档案会产生新编号，原码无法在新编号上使用。人工核实后可以协助恢复原档案。当前没有账号服务、在线撤销或设备绑定，复制整份档案仍会复制本地权限；这套流程适用于目前的本地档案原型。

## 验证

```sh
python3 tests/run_manual_safe_purchase.py
python3 tests/run_manual_safe_purchase.py --capture-manual
```

测试使用临时商家密钥和独立游戏档案，覆盖签名互通、内容篡改、错误商品/价格、购买编号绑定、交易单号复用、重复激活、存档恢复和输入框回车流程；不会生成真实订单或触碰你的发码记录。
